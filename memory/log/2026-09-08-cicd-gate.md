# 2026-09-08 (late) — CI/CD gate SHIPPED: nothing releases untested

**Ask (user):** "make a cicd pipeline for this project, where before every
deployment everything is tested automatically" — then "cicd moet in github
staan" (GitHub Actions, not something local).

**Found first:** `ci.yml` already tested every push/PR, but `release.yml`
published on a `v*` tag after typecheck+build only — the suite was NOT a
release gate (the morning's decision note had it under "rejected, revisit").
And the CI history held one red run on a memory-only commit: a flaky
teardown, see [[test-teardown-late-writer-race]].

## Landed (full dev-flow, 1 fix cycle)

- **`.github/workflows/verify.yml`** — reusable (`on: workflow_call`), the
  one definition of "verified": `check` (typecheck, build, icon check) +
  `test` (build, `npm test`). Same SHA pins, `persist-credentials: false`,
  per-job `contents: read`, header carries the node-pty-compiles-from-source
  and powershell-tests-self-skip facts.
- **`ci.yml`** → just `uses: ./.github/workflows/verify.yml`.
  **`release.yml`** → `verify` replaces its own `check`; publish
  `needs: [verify, host]`. Status-check names are now
  `verify / typecheck + build`, `verify / backend test suite`.
- **`npm run release -- vX.Y.Z [--dry-run]`** (`scripts/release.sh`) —
  refuses unless: tag `^v\d+\.\d+\.\d+$`, `gh` authed, clean tree, on
  `main`, `HEAD == origin/main` after a fetch, tag unused local+origin, and
  `gh run list --workflow CI --branch main --commit <sha>` newest run
  `success` (in-progress → refuse, no polling; failed → URL). Then
  `git tag -a` + `git push origin refs/tags/<tag>`. Every read that can fail
  is checked (`if ! VAR="$(…)"`). Inline `node -e` parses JSON from stdin,
  non-array = `BAD-JSON`; unit separator `\037` for the field join because
  `IFS=$'\t' read` collapses an empty conclusion.
- 30 tests via `git`/`gh` `/bin/sh` doubles on PATH with canned answers +
  a call log; ordering asserted by index (fetch before compare, tag before
  push), `--dry-run` pins the exact 8 read-only git calls + 3 gh calls.
- Flake fix (tests only): `destroyAllAndSettle` / `waitForLogLines` /
  `removeTempDir` in `tests/helpers.ts`, applied at 4 sites; `bodyThrew`
  guard so a settle timeout never masks the real assertion.
- README Release process rewritten; scope bullet + decision note updated.

## Review caught

- Scope: `finally` settle could **swallow the body's error** (MED);
  `countOccurrences('')` infinite loop with no `--test-timeout` (LOW);
  three `[ -n "$(git …)" ]` reads where a network failure reads as "tag is
  free" (LOW→MED); scope doc + decision note contradicting the code.
- Security: CLEAN; note → `git push origin refs/tags/$TAG` (a same-named
  branch makes the bare name ambiguous); `--branch main` filter.
- Test gate: fetch-before-compare was asserted by **membership, not
  order**; newest-run-wins lacked the discriminating direction (newest
  FAILED over older success) — mutants `find(success)`/`some` survived;
  dead `fetchCode` knob; `--help`, unknown option, gh-missing, not-a-repo,
  BAD-JSON uncovered. All added. Suite 878 → 908.

## Not done / open

- Branch protection / required status checks: open user decision (private
  repo; may not be available on the plan). Release gate does not need it.
- Server-side `destroyAll(): Promise<void>` + logger `close()` would make
  shutdown honest about late writes — follow-up candidate, not scoped.
- `workflow_dispatch` on `release.yml` now also runs the full suite (cost,
  not a defect).
- First push to `main` is the only proof of the reusable-workflow call on
  GitHub's side (`gh workflow view` reads the pushed ref).
