# 2026-09-23 — P5: inactive tabs stay alive

After P1–P4 ([[2026-09-23-quality-p1-p4]]) a switch to a 4-pane tab still
cost ~220 ms (xterm parsing the replay). The user: "doe het, p5". The
orchestrator set the bounds: at most `MAX_LIVE_TERMINALS` = 12, the least
recently seen tab evicted first (and replaying on return), a hidden pane
never acks attention.

| | Before | After |
| --- | --- | --- |
| Return to a 4-pane tab (already visited) | 1.37 MB, ~250 ms gap | 0 B, 32–39 ms |
| First visit | 1.37 MB, ~250 ms | unchanged |
| Memory at the cap (12 live) | — | +~140 MiB (≈ 17 MiB per terminal) |
| "Too many active WebGL contexts" in a 20-pane churn | 52 (without the release fix) | 0 |

- Parked cards live hidden in `div.pane-parking` on `<body>` (outside
  `.grid`, so no drop target, selector or keystroke reaches them);
  `web/src/ui/panes-park.ts`, eviction rule in `pane-reuse-model.ts`.
- Two acks (`onAttention`, `onInfo`) compared slot INDEXES, so a parked pane
  at index 0 would have acked its own BEL — gated on `isDrawn` before it
  shipped. The server raises attention from the BEL itself; no server change.
- The WebGL addon only removes its canvas on dispose; the context lived on
  until GC and counted toward Chromium's ~16. `dispose()` now calls
  `WEBGL_lose_context` on the addon's own canvases (52 warnings → 0).
- `/verify-terminal` caught a regression the unit tests could not: `top`
  (normal screen) came back torn after a window resize while its tab was
  parked. Cause: `show()` fitted while xterm's renderer was still paused —
  xterm learns it is visible again only from its own IntersectionObserver a
  frame later — so its scroll bookkeeping clamped 6 rows short and read it as
  a user scroll-up. `show()` now fits on its own IntersectionObserver's first
  visible report. Re-verified: top, vim, claude, counters, eviction, V4, V6.

One full-suite red on the way: `lifecycle` "history: every end reason …"
with `Time jumped backwards` in `dmesg` — the known WSL clock step
([[wsl-clock-steps-backwards]]); 3/3 alone and the re-run suite green,
no assertion touched.

## Worth remembering

- Hiding an xterm with `display:none` pauses its renderer; anything that
  resizes it must wait until xterm has seen it visible again.
- Index-based "is this the focused pane" checks break as soon as panes can
  exist outside the grid — compare identity, not position.
