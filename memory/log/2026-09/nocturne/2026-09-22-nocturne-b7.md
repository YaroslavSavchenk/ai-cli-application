## What landed

- **Where the rows come from.** Claude Code writes, per session,
  `<CLAUDE_CONFIG_DIR|~/.claude>/projects/<slug>/<session-id>/subagents/agent-<hex>.meta.json`
  (agent type, task, model) and `agent-<hex>.jsonl` (one event per line;
  assistant lines carry `message.id`, `stop_reason`, `usage`; one API
  message = several consecutive lines with the same id). The status-line
  payload carries `transcript_path`; `server/statusline.mjs` adds it verbatim
  (≤ 1024 chars, never `clean()`ed — it is a path) to the B1 snapshot.
- **The boundary** (`server/agents.ts` `subagentsDirFor` + a per-poll
  re-check): the snapshot is untrusted (the data dir is not a boundary), so
  a path is accepted only when absolute, `normalize(p) === p`, no trailing
  separator, no control character, `<uuid>.jsonl`, and the parent's realpath
  sits inside the real projects root; the directory actually opened is
  realpath-checked again on EVERY poll (the audit's probe followed a symlink
  planted at the `<uuid>` component). Reads: `O_NOFOLLOW | O_NONBLOCK`,
  `isFile()`, meta ≤ 8 KiB, transcripts incrementally by offset with a
  Buffer carry (a UTF-8 sequence may straddle a read), ≤ 4 MiB per file and
  ≤ 16 MiB per tick across everything, lines ≤ 1 MiB with resync, shrink →
  reset, ≤ 1024 metas scanned, ≤ 64 agents tracked.
- **A row.** name = agent type (`agent` when missing), task = description
  (control-stripped, 64/120), started = the first line's timestamp (the
  meta's mtime before there is one, never "now"), tokens = the billed total
  across unique `message.id`s (a 15-minute test-engineer reads `12.5M`; the
  output-only figure is the recorded flip), finished = the last
  user/assistant line is an assistant `end_turn` (a later `user` line makes
  it running again) or no growth for 15 min (a killed agent leaves no
  marker; 15 min > Claude Code's longest tool call). At the session's exit
  every running row becomes finished with the exit time — a subagent
  cannot outlive its host.
- **On the wire.** `SessionInfo.agents?: SessionAgent[]` inside the
  existing `info` frame: running first (oldest first), then ≤ 3 finished
  (newest first), ≤ 8 rows, re-sent on a real change only (`sameAgents`);
  tracking only for a live session (`isLive`), untracked at exit and
  removal, `stop()` at both shutdown sites; the last list stays after exit.
- **The browser.** `ui/pane-agents-model.ts` formats rows for the A3
  renderer (`0s` · `2m 10s` · `1h 05m` · `3d 02h`; `999` · `12.4k` ·
  `1.2M`), the 15 s status tick moves a running row's time, the table is
  never rendered empty and never for a non-claude session. The B9
  constraint landed with it: header/time/tokens/finished dot on
  `--xt-bright-black`, name on `--xt-fg`, task a 33 % mix (A3's three-step
  hierarchy on a two-step theme), both hairlines under the terminal a 30 %
  mix of the quiet step — the default pane unchanged to the pixel, a light
  custom ground readable.
- `claudeConfigDir()` in `server/config.ts` is now the ONE derivation of
  `<CLAUDE_CONFIG_DIR|~/.claude>` (history.ts's copy deleted).

## What the reviews found

- Security (2 should-fix, 1 nit, 0 blockers): the boundary stopped at the
  transcript's parent — a symlink AT `<uuid>` or `subagents` was followed
  (probe verified) → per-poll realpath check; a realpath RESULT reached
  server.log unsanitised → `oneLine()` at every path-carrying log line;
  `track` not gated on a live session → `isLive`.
- Scope (2 should-fix, 3 notes): `claudeProjectsDir` ignored
  `CLAUDE_CONFIG_DIR` (history.ts and the scope doc already honoured it —
  for such a user the table would never appear, silently); a refused path
  left no log line; the wiring seam untested; the scope doc bullet.
- Orchestrator: the 4 MiB cap was per file per tick — first sight of a
  30-agent session parsed tens of MB of JSON on the PTY thread → a global
  16 MiB per-tick budget.
- Verify-terminal (all PASS): the directory refusal was logged on every
  poll (54 lines in 110 s) → once per tracked directory; a running row
  kept ticking after its session exited → finished at exit.

## Process

- Two developers in parallel on one tree (backend-pty, terminal-ui), the
  protocol text written by the orchestrator first so neither waited; one
  bundled fix round (7 findings) to the SAME backend developer; one
  test-gate: 81 mutants, 72 killed, 9 equivalent, 0 live (full probe on
  `server/agents.ts`, ~12 on the UI model), +24 tests from the gate.
- Verify-terminal scoped on a scratch backend + the reused headless Chromium
  harness, with a `claude`-named bash wrapper as the session command (the
  backend injects `--settings`/`--session-id`, bash drops them) and rows
  planted under a scratch slug in the REAL `~/.claude/projects` (removed
  after, the boundary exercised end to end): table appears in ~2 s, the
  terminal refits 30 → 27 rows with ONE resize and no storm, 1 ↔ 2 panes
  correct, finished/resumed transitions, the 8/3 cap and order, themed ink
  on `#f4f1ea` (no selector on the app neutral, name = `--xt-fg`, quiet =
  `--xt-bright-black`), both refusals with their log lines, rows kept after
  exit, V1 / V3 / V4.
- Lesson: a boundary check on the INPUT path is not a boundary on the
  directory OPENED — every component joined after the realpath must be
  realpath'd again where it is used, on every use (a symlink can be planted
  after `track()`).
- Lesson: a per-file read cap on a polling watcher is not a cap on the tick;
  the budget must be global or the first poll of a big backlog stalls the
  thread that pumps every PTY.
