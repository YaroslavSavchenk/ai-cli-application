# 2026-09-22 — Nocturne B4 LANDED: the editor reads, saves, follows and survives

User: "continue werken aan de app" → B4 was the next row of the status table.
Spec `.claude/plans/nocturne/PLAN-B4.md`; decisions [[b4-editor-live]].
Four questions asked before the developer started (D1 every door asks, D2
tabs survive a reload, D3 a clean tab follows its file, D4 a save onto a
changed file is refused and the user chooses). The last mock module
(`web/src/ui/files-mock.ts`) went with this part — nothing in the app draws

## What landed

- **Phase 0 (orchestrator):** `FS_TEXT_MAX_BYTES`, `FsEol`, `FsReadResponse`,
  `FsWriteRequest`, `FsWriteResponse` in `shared/protocol.ts`; `fsRead` /
  `fsWrite` in `web/src/api.ts` — both developers ran in parallel on disjoint
  files, as B1 and B3.
- **Phase 1 (backend-pty):** `server/fstext.ts` — `GET /api/fs/read`
  (`if=<stamp>` → `{changed:false}`), `PUT /api/fs/write` (`expect` → 409 /
  404, absent = Overwrite, create branch for a gone file); the fd judged
  before the path is trusted (`O_NOFOLLOW|O_NONBLOCK`, regular file only);
  the stamp compared and the bytes written on ONE descriptor (in place:
  inode, mode, links, owner stay; read-only → 403); `decodeText` /
  `encodeText` (BOM, first-line-break `eol`, LF on the wire); SHA-256
  stamp; counts-only logging with the errno code on a 5xx.
- **Phase 2 (terminal-ui):** `file-pane.ts` reads on build (`Loading…`, the
  field, or the server's sentence); Save / `Saving…` / Ctrl+S on the
  textarea only; the conflict bar (`Overwrite` / `Load from disk`) in the
  pane's own 30 px strip; `editor-store.ts` (injected gateway, ONE 5 s
  follow timer, per-body skip rules, generation guard); `unsaved.ts` (the
  question in the delete dialog's shape, three guarded closers,
  `beforeunload`, `disarmUnloadGuard` for the app's own reloads);
  `state.ts` persists editor slots (16 tabs per strip at the landing, FOUR
  since the same-day amendment below; hostile bag gated,
  `dirtyLostBy`); `fake-dom.ts` learnt caret, scroll and visibility.

## What the reviews found

- **Scope, phase 1 (SHOULD):** the spec's JSON body cap of 4× was wrong —
  a C0 byte escapes to six (`\u001b`); a 1 MiB ANSI log read 200 and saved
  413. Factor 6, spec amended, ESC-file test.
- **Security, phase 1 (2 SHOULD, no MUST):** a unix socket answered 500
  with an error-level stack (`open(2)` fails ENXIO before any fd exists —
  the fstat rule never ran) → 415; **hard links** defeat the realpath
  boundary and the data-dir refusal (measured: the token came back in a
  body, `runtime.json` was overwritten in place). Decision: known limit,
  recorded in the module header, the scope doc and two pinning tests —
  same posture as the symlink TOCTOU; an `nlink > 1` refusal rejected
  (pnpm's store is hard links).
- **Security, phase 2 (2 SHOULD):** keystrokes typed while a write was out
  were marked clean when it landed (`saveEdit` deleted the newer entry) →
  forget only the text that was written; a follow answer could overtake a
  save and paint pre-save text with the old stamp, and a follow refusal
  dropped the field under a dirty tab → per-body generation guard, dirty
  check in the `.catch` too.
- **Scope, phase 2 (SHOULD):** `MAX_TABS = 16` was an undeclared limit →
  declared in the scope doc. Notes fixed: a dirty file whose boot read
  fails now keeps its field and offers Overwrite; diff roots must be
  absolute; stored paths capped at 4096; the discard question isolates
  the name's bidi; `beforeunload` disarmed before the restart handoff's
  reload.
- **Gates:** backend FULL probe 106 mutants — 90 killed, 16 equivalent with
  a measured reason (both `fsync`s, the realpath-side `O_NOFOLLOW`s, the
  FIFO `O_RDWR` open that the kernel never blocks), 6 tests added, no real
  defect; the FIFO test proved non-vacuous (dropping `O_NONBLOCK` hung the
  file for 120 s). Frontend capped probe 10 mutants — 9 killed, 1
  equivalent (a two-half guard), 1 test added (a hash that merely contains
  40 hex).

## Same-day amendment: four tabs per pane (`the user's Windows check`)

User: "volgens mij werkt alles, alleen ik kan oneindig veel tabs open
hebben, limiteer dat met 4. En als je een andere opent, dan sluit de 4de en
gaat een andere open." `MAX_TABS = 4` (files + diffs, persistence follows);
a fifth open evicts position 4 and lands there active; a tab already in the
strip is raised; a new pane never evicts; D1 holds — an evicted tab with
unsaved text no other tab shows gets the question first, `Keep editing`
cancels the open (orchestrator's default); moving a tab into a full pane is
refused with `This pane already holds 4 files.`, never an eviction on a
drag. Every opener in `web/src` now goes through `openFileGuarded` /
`openDiffGuarded` / `openTabAtGuarded` (`ui/unsaved.ts`), pinned by a
source scan. Found on the way: `opts?.done?.(st.openFile(…))` skips the
OPENER when `done` is absent — optional chaining short-circuits the whole
call including its arguments. Scope review: the commit view's "open before
close" pin had gone vacuous with the rename (`-1 < n`) — both indexes are
now required to exist; the scope doc gained the open-that-evicts as a
fourth door. Left: `'full'` on `OpenFileResult` carries two meanings (full
strip from `moveTab`, full tab of panes elsewhere) — a distinct member
would be type-enforced. Suite 3103 → 3127.

## Process notes

- The spec's own arithmetic was the phase's worst bug (4× vs 6×). A cap
  derived from an encoding needs the encoding's WORST case written beside
  it, not a round factor.
- "What did the measured list miss" in the security brief paid again:
  the developer had measured FIFOs and symlinks; the auditor found the two
  objects the list did not name (a socket, a hard link).
- Two developers in parallel on a frozen protocol, readers per phase, one
  bundled fix round per phase, gates after the readers — B1/B3's shape,
  no collisions.
