# 2026-09-22 — Nocturne B9 LANDED: Terminal colours live

User: "continue met bouwen van de app" → B9 was the next row of the status
table. Spec `.claude/plans/nocturne/PLAN-B9.md`; the shape was already
decided ([[terminal-colours-shape]], open decision 10); no question needed
the user — the persisted shape, the surface split and the write policy are
orchestrator defaults, recorded in the spec before the developer started.
The last mocked surface of the Settings dialog is gone.

## What landed

- **The pair.** `prefs.theme = { ground, text }` (lower-case hex), the
  preset recovered from the pair by `matchPreset`, never stored; the Legacy
  `{ bg, fg, scan }` index shape still read one member at a time, never
  written again; `scan` left the protocol. `ui/theme-model.ts` owns the
  clamp and the hex rule (`isHex6`/`normHex` moved there, re-exported by the
  page model).
- **Nocturne = the absence of an override.** `ui/theme.ts` `apply` writes
  the six `:root` slots from `coloursOf(stateOf(pair))` — the SAME function
  the page's preview uses — and for the default pair REMOVES them, so
  `tokens.css` stays the one source of the default. Then
  `refreshAllTerminalThemes()` (`term.options.theme` only, no resize, no
  attach).
- **Terminal only, at the CSS seam.** `.pane-tab.is-on`, `.diff-body`, the
  new `.pane-file, .pane-diff` and `.pane.is-editor .pane-body` sit on
  `--color-term` (the untouched oklch twin); the terminal card, xterm's
  viewport, `--xt-bg` and `--xt-cursor-accent` follow `--term-bg`; the
  pane status bar's ink takes `--xt-bright-black` / `--xt-fg` so it stays
  readable on any ground.
- **Live, then persisted.** Paint + localStorage at once; the server write
  (`updatePrefs({ theme }, DEAD_PREFS_KEYS)`) 300 ms trailing-debounced and
  serialised (one in flight, one queued follow-up with the latest pair),
  `flush()` on dialog close; boot = cache first, a readable server pair wins,
  both before `initPanes`. The page gets the control injected
  (`SettingsDeps.theme`), imports nothing from theme.ts/terminal.ts.

## What the reviews found

- **A reopen race** (scope): closing the dialog flushes fire-and-forget;
  reopening before that PUT landed re-read a stale bag, repainted the OLD
  pair and scheduled a PUT of it — the durable copy would have been the old
  pair. Fixed with `ThemeControl.adopt(pair)`: paint + cache, no write back,
  a no-op while a write is pending or in flight; the re-read adopts.
- **`api.updatePrefs` wiped the bag on a failed GET** (scope, pre-existing):
  it PUT the bare patch, resetting `statusLine`, `behaviour`, `tools` to
  factory. B9 made that the hot path (every card click). Now it rejects;
  every caller already catches and reverts its row. The status-line
  `persist()` catch was silent — it warns now.
- A bare editor body on the themed ground (an editor pane with no drawable
  tab): `is-editor` on the pane root, toggled in `buildEditorPane` /
  `teardown`.
- Known limit recorded: the default card previews `RAMPS[0].cmd = #e9e9ed`
  while the default terminal's bright white is the token `#f3f5fe` (the A1
  parity test pins the ramp to `--xt-cursor`); typing `#f3f5fe` yields a
  custom pair. B7 constraint: the agents table's ink and the two hairlines
  under the terminal are still app neutrals.
